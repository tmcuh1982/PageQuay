# PageQuay 1.2.0

[Français](1.2.0.md) | [English](1.2.0.en.md)

Local release, 19 October 2026. This commit does not publish a tag, GitHub release
or packages, and does not install or restart a service. Dobot acceptance and
UniversRobot integration remain subject to separate approval.

## Opt-in GIF and originals up to 20 MB

`POST /v1/projects/{slug}/download_image` retains its existing job and receipt.
Strict integer `max_bytes` keeps the **5000000** default and accepts at most
**20000000 bytes**. Optional `allowed_media_types` preserves JPEG/PNG/WebP when
omitted; a closed, nonempty, duplicate-free list explicitly enables GIF.
No new required receipt field.

The client requires `x-pagequay-image-contract=original-gif-20mb-v1` before an
extended POST, in addition to the existing transport marker. `--max-bytes` and
`--allowed-media-types` expose these options. A lost POST response remains
uncertain: no automatic replay; follow the same job when its ID is known.

GIF87a/GIF89a receives a full structure walk through the trailer, including data
after the first image; only the first image is decoded. Logical screen and all
descriptors: ≤8192 per axis, ≤16000000 pixels, ≤1000 images, contained images.
The disposable validator has five CPU seconds and ten wall seconds within the
total deadline. No PageQuay preview, screenshot, coalescing or reencoding.

Chromium retains exact-URL, HTTPS/TLS, redirect, public DNS/IP and project guards.
Storage accepts 20 MB originals within existing quotas. Private original GET is
bounded to the recorded size, checks the opened file, ignores Range for complete
HTTP 200 and closes the file after success, failure, cancellation or timeout.
The client checks its expected project, status, MIME, size and SHA256 before
renaming the private output.

## Validation and limits

- General suite: **343 passed, 123 skipped**, 14.37 s.
- Targeted real Chromium suite: **164 passed**, 139.41 s; suites overlap.
- Targeted Ruff check/format, OpenAPI, diff --check and offline lock validation pass.
- Valid boundary fixtures at 5000000/5000001 and 20000000/20000001 bytes;
  truncation, misleading responses, SSRF/scope/isolation, timeout/cancellation,
  resume/cleanup and existing iframe/TIMEOUT regressions retained.
- Four concurrent 20 MB acquisitions passed with verified hashes and 80 MB of
  fixture-project artifacts removed. Sampled test-process-tree RSS peak: about
  2.48 GiB, including Chromium and the fixture server.

No OS RSS ceiling is guaranteed on macOS; bounded application blocks do not cap
Chromium internal buffers. Later GIF frames' pixels are not decoded and their
decodability is not guaranteed. False short HTTP lengths may hide bytes beyond
message framing. Initial navigation and the second GET can differ. After headers,
a failed transfer aborts without replacement JSON; clients must retain the receipt
and check integrity. Validation is not antivirus scanning. The pre-existing
Starlette/httpx deprecation remains.

Source/module/contract/project-lock metadata declare **1.2.0**, without changing
dependency versions. Installed sources checked remain **1.1.1**. Existing Pillow
attribution and warnings in the working tree are retained in bilingual docs.
