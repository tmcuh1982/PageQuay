# PageQuay 0.2.4

[Français](0.2.4.md) | [English](0.2.4.en.md)

Preserves Playwright initialization/guards while launching Chrome/Chromium on an explicit local CDP port. Page WebSockets are refused through the native browser proxy without replacing JavaScript WebSocket.

## Changes

- Private pipe relay to child-specific nonzero 127.0.0.1 CDP port, with endpoint validation/startup/cancel/shutdown cleanup.
- Two profile proxy listeners: validated public HTTP/HTTPS and pre-DNS/upstream WebSocket denial. No direct fallback; frames/popups/workers covered.
- Removes context.route_web_socket; preserves native constructor, sandbox/interceptions/redirects/Service Workers/permission/download guards.
- Direct websockets>=15,<18 dependency; public schema unchanged except version, no new migration.

## Validation

Full PQ_BROWSER_TESTS=1 pytest: **343 passed/four skipped**, 95.71 seconds, existing Starlette/TestClient/httpx warning. Targeted Ruff/format, uv lock --check --offline and diff pass. Package/module/OpenAPI/lock at 0.2.4. CDP lifecycle/proxy cleanup/positive and guarded WebSocket cases covered.

Installed Chrome then Chromium fresh profiles successfully searched/opened Music Store; five further searches/product pages in one retained Chromium session returned HTTP 200 without observed challenge. First click timed out, then pages were opened via observed links. [Evidence](../BROWSER_TRANSPORT.en.md).

## Installation and limits

chromium stays default, chrome selects installed Chrome. Normal update preserves profiles/keys/settings. Local CDP is unauthenticated: trusted local processes only; never proxy/Serve it. No guarantee of future site availability or automatic CAPTCHA solving.

At this historical stage runtime fix was deployed with installed metadata 0.2.2; this 0.2.4 commit prepared sources without closing the demonstration session, claiming neither GitHub publication nor package reinstall.
