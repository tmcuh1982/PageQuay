# PageQuay 1.2.4

[Français](1.2.4.md) | [English](1.2.4.en.md)

26 October 2026 release: CAPTCHA safeguards, visible verification windows and
more reliable Chromium startup.

- Human intervention shares a 120-second deadline per job by default
  (`PQ_HUMAN_TIMEOUT_SECONDS`). Resuming does not reset that deadline.
- Automatic checks are spaced one second apart. Each wait sequence creates at
  most one screenshot; extraction stops after three discarded CAPTCHA captures.
- After a CAPTCHA wait expires or is cancelled, loading stops, JavaScript is
  disabled and the page is suspended. If suspension fails, PageQuay attempts to
  close the tab. An explicit navigation, action or extraction reactivates a
  suspended page. These safeguards are not OS CPU or memory limits.
- When human intervention is required, a minimized window is restored and the
  CAPTCHA tab is brought to the front. Headless mode is skipped; presentation
  failure does not prevent manual job resumption.
- Window operations and screenshot preparation have bounded deadlines. Slow native
  macOS minimization confirmation no longer closes an otherwise healthy browser.
- `POST download_image?wait_seconds=0..10` may return HTTP 200 with the completed
  job; otherwise HTTP 202 with the same ticket. Default behavior stays asynchronous,
  without implicit replay or cancellation. Access is checked again after waiting.

OpenAPI and package versions advance to 1.2.4. Dependencies, network guards and
exact URL contracts are unchanged.

Validation: general suite, 389 passed and 178 skipped; targeted validation with
Chromium, 36 passed (CAPTCHA, windows, images and OpenAPI). Ruff, formatting and
diff checks pass. Native macOS presentation is covered by simulated window
commands; timer suspension is checked in real Chromium.
Packages: wheel, source archive and SHA256SUMS. Restart the service after installing
the release to load the updated code.
