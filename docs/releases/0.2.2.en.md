# PageQuay 0.2.2

[Français](0.2.2.md) | [English](0.2.2.en.md)

Improves exact-URL acquisition, fixes isolated KUKA iframe context selection and separates navigation/challenge handling/extraction.

## Changes

- Main-document evidence on navigation/artifacts: requested/final URL, nullable HTTP status, Content-Type, redirect chain and navigation ID.
- allow_redirects=true by default independent of robots; intermediate targets retain network guards. Explicit false still refuses before follow.
- Passive bounded automatic checks including cf-mitigated: challenge; human waiting then same-job /resume.
- Different expected final URL yields scope_changed for review, no business extraction/implicit adoption. Challenge-invalidated captures discarded.
- WORLD_NOT_FOUND fix uses native frame slots and owning CDP targets, including internal OOPIF descendants; missing/path-mismatch diagnostics distinct.
- Correlated IDs, idempotent create/navigation, DOM/XPath provenance, opt-in robots and checkpoint server client with explicit recover/cancel/resume.

## Validation

General Chromium: **265 passed/four skipped**; final **48 targeted** plus **five browser/Cloudflare regressions**, overlapping. Ruff/public OpenAPI/offline lock verified. Real disposable KUKA: exact final URL, 69 main blocks, f1 extracted, no partial/truncation. Player had zero mounted text. No demonstrated causal link between the CDP defect and redirects/Cloudflare, and no real Cloudflare challenge solved.

0.2.2 locally deployed/verified with keys/projects/settings unchanged. Existing-private-key installed validation remained assigned to UniversRobot.

## Installation and limits

Source/Python packages; additive migration 007_job_correlation.sql on startup. In-memory tab IDs do not survive restart. Network/isolated-world/budget controls remain; strict HTTPS child-frame network denial persists because all OOPIF redirects are not attested. At this historical release the custom PageQuay/0.2.0 User-Agent was retained; later 0.2.3 restored native Chromium agent.
