# PageQuay 1.0.0

[Français](1.0.0.md) | [English](1.0.0.en.md)

Première release v1 de PageQuay, passerelle privée de navigation pour macOS : profils persistants séparés, API REST/WebSocket par projet, recherche, actions, extraction et captures. Elle reprend le commit validé 0.2.4, avec les métadonnées paquet/module/OpenAPI/lock alignées sur 1.0.0 ; le code navigateur ne change pas entre ces deux commits.

## Fonctionnement livré

- Console locale française, clés API à scopes et quotas, jobs asynchrones, artefacts protégés et profils isolés.
- Recherche multi-adaptateurs, navigation avec contrôle de portée/redirections, extraction bornée du DOM et des iframes, captures et diagnostics filtrés.
- Action `validate_cookies` et choix automatique par projet, désactivé par défaut ; acceptation explicite et résultat du clic observé.
- User-Agent natif et contexte persistant Playwright. Chrome installé ou Chromium fourni par Playwright ; `chromium` reste le défaut.
- Relais privé du pipe Playwright vers un port CDP explicite non nul sur `127.0.0.1`, propre au navigateur enfant, avec validation d’endpoint et nettoyage.
- Refus natif des WebSockets des pages par un second listener proxy, avant DNS/connexion amont, sans remplacer le constructeur JavaScript `WebSocket` ni prévoir de repli direct. Frames, popups et workers couverts ; WebSocket de commande PageQuay disponible.
- Sandbox, proxy public à IP validée, contrôles de redirections, Service Workers, permissions et téléchargements conservent leurs gardes.

## Validation

Code de base : suite complète Chrome/Chromium `PQ_BROWSER_TESTS=1 .venv/bin/pytest -q`, **343 tests réussis, 4 ignorés**, warning Starlette/TestClient/httpx préexistant. Ruff ciblé, format, lock offline et diff-check conformes. Passage à 1.0.0 : **6 tests de contrat public réussis**, lock offline, Ruff et diff-check conformes.

Service installé : Chrome puis Chromium en profils neufs, recherche et fiche Music Store réussies. Dans une même session Chromium conservée, cinq recherches et cinq fiches distinctes ont répondu en HTTP 200 sans défi Cloudflare observé. Le premier clic Fender a expiré ; les fiches ont ensuite été ouvertes via navigation API vers les liens observés. [Protocole et limites](https://github.com/tmcuh1982/PageQuay/blob/v1.0.0/docs/BROWSER_TRANSPORT.md).

## Archives

La release fournit `pagequay-1.0.0-py3-none-any.whl`, `pagequay-1.0.0.tar.gz` et `SHA256SUMS`, construits depuis le commit du tag. Les ressources JavaScript, templates, assets et migrations sont inclus dans le wheel ; les sources comprennent les scripts et la documentation. Aucune base, clé API, configuration privée, capture ou profil navigateur n’est distribué.

## Installation et limites

Python >=3.12,<3.15 et macOS avec session graphique pour le mode visible. Installer les dépendances et Chromium selon le [README](https://github.com/tmcuh1982/PageQuay/blob/v1.0.0/README.md). Les migrations additives existantes sont appliquées au démarrage ; aucune migration supplémentaire n’est introduite par le passage à 1.0.0. Profils, clés et réglages sont conservés lors d’une mise à jour normale.

Le port CDP local n’a pas d’authentification propre : réserver son accès aux processus locaux de confiance et ne jamais le publier par proxy, tunnel ou Tailscale Serve. Le proxy ne remplace pas un pare-feu OS. Aucun CAPTCHA n’est résolu automatiquement et l’accès futur aux sites protégés n’est pas garanti. Les recettes d’accès depuis un autre appareil, ACL Tailscale et restauration complète restent partielles.

La publication GitHub n’installe pas le paquet dans le service existant. Celui-ci conserve ses métadonnées 0.2.2 et sa configuration Chromium ; son correctif runtime a déjà été déployé et la session de démonstration n’est pas redémarrée par la publication.
