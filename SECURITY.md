# Sécurité PageQuay

## Périmètre et invariants

Application privée pour un opérateur et des clients connus. Les pages Web sont non fiables ; les clés API et profils sont des secrets. Chaque ressource possède une relation serveur vers un projet identifié par un ID aléatoire. Les slugs ne deviennent jamais des chemins. Aucun administrateur par défaut, API d'administration pour clés clients, CDP public ou exécution de code fourni par un client.

Sessions serveur : token aléatoire de 256 bits, hash SHA-256 dans SQLite, durée absolue de 12 h et inactivité de 30 min ; nouvelle session au login, précédente invalidée, logout et CSRF pour chaque mutation UI. Cookies HttpOnly, SameSite Strict et Secure lorsque configuré pour HTTPS. Login CSRF également protégé et limité à cinq tentatives par transport/cinq minutes avec limite globale. Mots de passe Argon2id, minimum 14 caractères. Les erreurs ne renvoient pas les valeurs invalides des formulaires.

Clés API : 256 bits CSPRNG, hash SHA-256, comparaison en temps constant après lookup, projet unique et scopes explicites. Pour des secrets aléatoires de cette entropie, un hash rapide ne rend pas la recherche exhaustive réaliste ; les mots de passe humains ont, eux, un hash lent Argon2id. Préfixe d'identification non secret, affichage complet une fois, expiration/révocation revalidées pour requêtes, jobs actifs et WebSockets. La modification d’une clé est réservée à une session admin locale avec CSRF : secret/projet conservés, aucune réactivation d’une clé révoquée, date future ou absence d’expiration, au moins un scope reconnu et quota borné. Le compteur de quota est conservé ; les jobs utilisant un droit retiré sont annulés et les requêtes suivantes revalident les droits. Audit `key.updated` sans secret. Pas de secrets complets dans le journal d’audit.

## Contrôle local du navigateur

Le navigateur enfant utilise un port CDP explicite non nul sur `127.0.0.1`. Le relais conserve l’initialisation Playwright et valide l’adresse, le port et le chemin de l’endpoint annoncé par son propre enfant ; il ne recherche pas un navigateur existant. Le pipe de Playwright se termine au relais, sans être transmis à Chrome. EOF, annulation, timeout ou échec du transport entraînent le nettoyage du navigateur enfant.

Ce port CDP n’ajoute aucune route publique ni commande arbitraire à l’API. Il n’a pas d’authentification propre : les processus locaux capables d’y accéder appartiennent au périmètre de confiance de l’opérateur. Ne pas le publier par proxy, tunnel ou Tailscale Serve. Les pages restent soumises au proxy et au refus des destinations loopback. Voir [transport navigateur](docs/BROWSER_TRANSPORT.md).

## Egress navigateur

Le proxy propre à chaque profil écoute sur une adresse loopback et un port éphémère. Il analyse URL/schéma/port, vérifie **toutes** les réponses DNS et connecte directement une IP validée. TLS reste vérifié par Chromium à l'intérieur du tunnel CONNECT. Les sous-requêtes sont aussi interceptées par Playwright ; le proxy reste le contrôle de connexion, y compris quand une redirection échappe à l'interception. Loopback, réseaux privés, link-local, tailnet CGNAT, multicast, réservés, IPv6 mapped/6to4/Teredo/NAT64 standard, métadonnées cloud et littéraux IP ambigus sont refusés. Ports publics 80/443 seulement. Liste autorisée exacte ; liste bloquée couvre aussi les sous-domaines.

Chromium est lancé avec `chromium_sandbox=True` : Playwright le désactive sinon par défaut ([documentation officielle](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-option-chromium-sandbox)). QUIC et UDP WebRTC non proxifié sont désactivés ; WebSockets distants et service workers bloqués. Le refus des WebSockets `ws`/`wss` utilise un second listener proxy loopback qui rejette avant DNS ou connexion amont, sans remplacer l’objet JavaScript `WebSocket`. La catégorie Chromium `socks=` (« autres proxys ») vise ce listener avec une URI de proxy HTTP explicite ; aucun repli `DIRECT` n’est configuré. Les frames, popups et workers sont couverts ; la fermeture de ce listener ne rétablit pas un accès direct. Le WebSocket de commande PageQuay n’est pas concerné.

Permissions caméra, micro, localisation et clipboard non accordées. Téléchargements annulés, uploads et accès arbitraires aux fichiers non exposés. Les dialogues sont fermés sans validation de challenge.

Ce dispositif **n'est pas un pare-feu OS** : un navigateur compromis, une extension ajoutée manuellement, un processus local autorisé ou une modification manuelle du profil sortent du modèle de confiance. Les tunnels ne déchiffrent pas les requêtes HTTP internes à TLS et ne garantissent pas une politique par URL à eux seuls. Le filtrage par origine, Playwright et l'IP de connexion s'appliquent conjointement. Une infrastructure exigeant un confinement complet doit ajouter un contrôle réseau OS administré. Aucune exception LAN de production dans cette version. Les exceptions des tests sont injectées uniquement en Python dans leur processus.

## Administration, stockage et contenu

Deux listeners imposés à 127.0.0.1 par la CLI : administration locale sur 8765 et API seule sur 8766 par défaut, ports distincts configurables. Le port API local peut être enregistré depuis la console même sans accès externe. Le port de destination réel de la socket limite le listener API à `/v1/`, aux deux routes health et au contrat client `/openapi.json`, pour HTTP et WebSocket ; aucun Host, proxy header ou cookie admin ne lève cette restriction. Transport non loopback refusé par l’application, Host et Origin explicites. Accès distant via Tailscale Serve HTTPS vers **le port API uniquement**, identité/ACL tailnet puis clé API. Le port admin ne doit jamais être publié par un proxy. Pas de Funnel. CSP locale, anti-framing, nosniff, no-store, referrer policy, réponse maximale, queues/onglets/navigateurs/actions/rate limits/artefacts bornés.

Templates Jinja échappés ; JavaScript utilise `textContent`, pas `innerHTML` pour le contenu externe. HTML extrait distribué comme pièce jointe avec CSP sandbox. Captures protégées par session admin ou scope projet. Pages distantes jamais intégrées en iframe. Si un client transmet du contenu à un LLM, traiter ce contenu comme des données non fiables et ne pas suivre ses instructions.

Dossiers 0700 et SQLite/artefacts/verrous 0600, umask 077 dans la CLI. Le profil reste lisible par l'utilisateur macOS et contient des cookies/secrets en clair ; aucune promesse de chiffrement au repos. FileVault est un contrôle macOS séparé. Verrou flock par profil, libéré par le noyau après crash. Reset manuel uniquement, deux confirmations et intention courte liée à la session ; refus si jobs en attente/actifs. Sauvegarder uniquement après arrêt complet.

L'audit conserve action, date, acteur ID, projet, identifiants de job/onglet, fonction, URL de navigation/ressource/destination, code HTTP et taille du corps de réponse encodé lorsqu’elle est disponible. À la demande de l’opérateur, les paramètres d’URL et fragments sont conservés en clair avec leur encodage d’origine ; seule la partie userinfo (identifiants de connexion intégrés à l’URL) est retirée. Les URL peuvent donc contenir des données privées ou jetons propres au site. Les libellés de pagination sont des valeurs reconnues fixes, aucun texte arbitraire de bouton ni sélecteur ou valeur de formulaire n’est enregistré. Aucun en-tête Authorization ou Cookie, identifiant de connexion userinfo, corps POST, HTML ou screenshot n’est journalisé. Les valeurs présentes dans une URL restent enregistrées comme paramètres ou fragments. Les erreurs conservent uniquement un code contrôlé, sans message brut du navigateur. Consultation réservée à la session admin locale, rétention d’audit habituelle et échappement Jinja. Les access logs Uvicorn sont désactivés. Les fichiers de logs LaunchAgent sont sous la responsabilité de l'opérateur ; rotation documentée dans `docs/OPERATIONS.md`. Ne pas activer DEBUG/trace Playwright sur des sessions réelles sans examiner ce qu'il enregistre.

Les lectures de titres, challenges, HTML, texte, liens, métadonnées et DOM structuré utilisent un monde Chromium isolé, avec limites appliquées avant le retour du contenu. Les titres sont limités à 512 caractères avec indicateur de troncature ; le contenu trop volumineux échoue en 413. La résolution des frames ne récupère pas l’arbre complet ni les titres des targets. Les résultats et erreurs de jobs sont également bornés avant persistance, y compris les résultats partiels et historiques surdimensionnés.

Le journal possède des files d’admission bornées, des quotas globaux/par projet, des plafonds en lignes et octets logiques et une réserve séparée pour les opérations administratives. Les requêtes en attente et tâches de collecte des tailles sont plafonnées ; les commits SQLite sont regroupés sur une connexion détenue par un worker. Le serveur n’attend pas ce worker sur sa boucle événementielle. Les totaux API sont coalescés séparément du détail et la console signale saturation, regroupement ou erreur d’écriture. Les plafonds ne garantissent pas la conservation exhaustive de l’audit ni une réduction immédiate du fichier SQLite. Un arrêt brutal peut perdre la dernière fraction de seconde non persistée. Ils ne plafonnent pas la mémoire propre de Chromium ou du driver Playwright ; un confinement OS reste nécessaire si une limite globale de ressources est requise.

## Vérification et signalement

Consulter `docs/testing/REPORT.md`. Les fixtures vérifient des mises en page connues, pas la disponibilité des moteurs. Les tests de crash ferment volontairement un contexte ; ils ne reproduisent pas tous les cas de panne OS. Tailscale ACL, LaunchAgent au login et restauration d'une sauvegarde doivent être validés sur la machine cible.

Pour signaler un défaut, conserver les étapes de reproduction et identifiants non sensibles. Ne pas joindre de profil navigateur, clé API, copie brute de page authentifiée ou capture contenant des secrets à un dépôt public.
